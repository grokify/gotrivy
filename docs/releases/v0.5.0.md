# Release Notes - v0.5.0

## Overview

This release adds conversion of Trivy reports to the shared **findingspec**
finding model and introduces a `trivy fs` scan wrapper with a new
`cmd/gotrivyscan` CLI. It also updates dependencies, including Trivy v0.75.0
(Go 1.27).

## Highlights

- Trivy reports now convert to the shared
  [findingspec](https://github.com/plexusone/findingspec) IR — a scanner-neutral
  finding model, so Trivy results can be aggregated and reported alongside
  findings from other tools using one common schema.
- New `ScanFilepath` wrapper and `cmd/gotrivyscan` CLI run `trivy fs` and return
  a parsed report.

## Added

### findingspec conversion

Trivy report results convert to the canonical `findingspec.Finding` (security
domain), one finding per vulnerability, with typed CVSS, fix state, and package
metadata:

```go
r := gotrivy.Report{Report: &trivyReport}
set := r.Findings(gotrivy.FindingSpecOptions{})
// *findingspec.FindingSet — feed to dashboards, prioritization, or export
```

### `trivy fs` scanning

`gotrivy.ScanFilepath` runs `trivy fs --format json --scanners vuln <path>` by
shelling out to the installed `trivy` binary and returns the parsed
`types.Report`, keeping the library lightweight (no Trivy scanner dependencies):

```go
report, err := gotrivy.ScanFilepath(context.Background(), "./target")
```

The new `cmd/gotrivyscan` CLI scans a path and writes an XLSX report.

> For in-process scanning that imports Trivy as a Go library (no `trivy` binary
> required), see the separate
> [`github.com/grokify/gotrivyext`](https://github.com/grokify/gotrivyext)
> module.

## Fixed

- Restored a consistent `go.sum` after a dependency-update merge left entries
  missing, fixing `go build`/`go test` on `main`.

## Dependencies

- Added `github.com/plexusone/findingspec` v0.1.0.
- Bumped `github.com/aquasecurity/trivy` to v0.75.0 (Go 1.27),
  `github.com/grokify/mogo` to v0.75.0, and `github.com/grokify/gocharts/v2` to
  v2.27.1.
